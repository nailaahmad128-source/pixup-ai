# PixUp AI

A premium, minimal AI photo & video enhancer app built with Flutter and
Material 3. This package contains the complete `lib/` source code and
`pubspec.yaml` — follow the steps below to turn it into a runnable
Android project on your machine.

**The AI enhancement engine is real, not simulated:**
- **Photos** are enhanced by **Real-ESRGAN** (BSD-3-Clause, free & open
  source), run fully on-device via **ONNX Runtime** — genuine neural
  super-resolution, fully offline.
- **Videos** are enhanced by a real **FFmpeg** filter pipeline (denoise
  → sharpen → contrast lift → high-quality upscale), with an optional
  per-frame Real-ESRGAN neural pipeline for short clips.

## 1. Finish the local Gradle setup

A complete `android/` project (Gradle Kotlin DSL build files,
`AndroidManifest.xml`, `MainActivity.kt`, launcher icons, ProGuard rules)
ships with this bundle, so you do **not** need to run `flutter create`.
Two machine-specific pieces can't ship in source control and need a
one-time local step:

1. **Gradle wrapper jar** — run `flutter build apk` or open the project
   in Android Studio once; either will fetch `gradle-wrapper.jar`
   automatically using the `distributionUrl` already set in
   `android/gradle/wrapper/gradle-wrapper.properties`. (If you'd rather
   do it explicitly: `gradle wrapper --gradle-version 8.10.2`.)
2. **`android/local.properties`** — auto-generated by Android Studio /
   `flutter run` on first build; contains your local `flutter.sdk` and
   `sdk.dir` paths and should never be committed.

If you ever do want iOS or the other desktop targets, run
`flutter create --platforms=ios .` — it will only add the missing
platform folders and won't touch the existing `android/` project.

## 3. AI Model Setup (required for real photo enhancement)

This repository does **not** include the Real-ESRGAN model weights —
they're a multi-megabyte binary file not appropriate to hand-author.
You need to add one real, free, open-source ONNX export yourself:

1. Get an official/community Real-ESRGAN ONNX export. Two good options:
   - Convert it yourself from the official PyTorch weights at
     https://github.com/xinntao/Real-ESRGAN (BSD-3-Clause) using their
     documented `torch.onnx.export` path — this guarantees you know
     exactly what you're bundling.
   - Use an existing, reputable community ONNX conversion of
     `RealESRGAN_x4plus` (search "Real-ESRGAN onnx" — several
     maintained conversions exist). Verify the license before
     distributing.
2. Rename the file to `realesrgan_x4.onnx` and place it at:
   ```
   assets/models/realesrgan_x4.onnx
   ```
3. Open the file in https://netron.app and check the **input** and
   **output** tensor names. Update these two constants in
   `lib/core/constants/app_constants.dart` if they differ from the
   defaults:
   ```dart
   static const String realEsrganInputName = 'input';
   static const String realEsrganOutputName = 'output';
   ```
4. If the model's native scale factor isn't 4x, update
   `realEsrganScale` to match.

Until the model file is added, the app builds and runs fine — the photo
enhancer will simply throw a clear, descriptive error (shown in a
snackbar) telling you exactly what's missing, instead of silently
faking a result.

## 4. Android configuration

Already done in `android/app/src/main/AndroidManifest.xml` and
`android/app/build.gradle.kts`: gallery permissions, `minSdk 24`
(`ffmpeg_kit_flutter_new` requires API 24+; `onnxruntime` requires
API 21+), `targetSdk 35`, ProGuard keep rules for the ONNX/FFmpeg
native bridges, and app icons. Nothing to add here.

### Release signing (required before Play Store upload)

The app currently signs release builds with the debug key so
`flutter build apk --release` works out of the box for testing. Before
uploading to Play Console:

1. Generate a keystore: `keytool -genkey -v -keystore ~/pixupai-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias pixupai`
2. Create `android/key.properties` (already gitignored) with:
   ```properties
   storePassword=<your store password>
   keyPassword=<your key password>
   keyAlias=pixupai
   storeFile=/absolute/path/to/pixupai-release.jks
   ```
3. Rebuild — `android/app/build.gradle.kts` automatically detects
   `key.properties` and switches release builds to it.

## How the real enhancement engines work

### Photos — Real-ESRGAN via ONNX Runtime
1. The selected photo is decoded and, if very large, downsized
   (preserving aspect ratio) to `realEsrganMaxInputDimension` — a
   deliberate mobile performance/memory safeguard, not a quality
   shortcut: the network still performs real 4x super-resolution on
   the (resized) image.
2. The image is split into overlapping tiles (`realEsrganTileSize` +
   `realEsrganTilePad` context border each side) — the same tiling
   strategy Real-ESRGAN's own CLI uses — so peak memory stays bounded
   regardless of the original photo's resolution.
3. Each tile is run through the real Real-ESRGAN ONNX graph, cropped
   back to its own region, and composited into the final upscaled
   image.
4. Result is saved as a JPEG in app storage and returned to the UI —
   same before/after slider, save, and share flow as before.

### Videos — FFmpeg (+ optional neural frames)
1. **Default path:** the whole video is passed through one real FFmpeg
   filter chain — `hqdn3d` (denoise) → `unsharp` (sharpen) → `eq`
   (contrast/saturation) → `scale` with Lanczos resampling (upscale) —
   re-encoded with `libx264`. Fast enough for typical clips on a phone.
2. **Short clips (≤ `neuralVideoDurationLimit`, default 8s):**
   additionally eligible for a slower, higher-quality path that
   extracts every frame, runs each one through the *same* Real-ESRGAN
   engine used for photos, and reassembles the video with the original
   audio track re-muxed in. This is real neural video super-resolution,
   but is deliberately capped to short clips because per-frame neural
   inference is expensive on mobile hardware — a longer video would
   take a very long time and risk OOM. If this path fails for any
   reason (e.g. model asset missing), it falls back to the filter-chain
   path automatically.

## Connecting a different/cloud AI engine later

Every screen depends only on the `AIEnhancementService` interface in
`lib/data/services/ai_enhancement_types.dart`. To swap engines (a newer
model, a cloud API, GPU delegate tuning, etc.), implement that
interface in a new class and swap the instantiation in
`photo_enhancer_screen.dart` / `video_enhancer_screen.dart`
(`RealAIEnhancementService()` → your class). No other file needs to
change.
